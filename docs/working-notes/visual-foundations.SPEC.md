This specification records the shared understanding reached in the July 16,
2026 visual-foundations grilling session. Its requirements govern the next
investigation; they do not promote the investigation's output into Jukkai
strategy, approved brand guidelines, or production canon.

The next agent should use this specification to write a detailed Figma execution
prompt. That later prompt may define tool sequencing, frame construction, asset
imports, and review loops. This specification owns the intended outcome,
authority boundaries, requirements, evidence, acceptance criteria, and explicit
non-goals.

## 1. Problem

Crystelle needs business cards and A5 flyers quickly and is currently making
composition, font, hierarchy, spacing, and color decisions in isolation in
VistaPrint/Canva. Those decisions risk becoming Jukkai's de-facto identity before
a visual system exists.

Martin has useful visual judgment, reference research, font candidates, base
colors, wordmark work, and unresolved color experiments, but too much of the
decision model remains implicit. The immediate need is therefore not a complete
design system. It is a visible foundation that:

- narrows the field of possible choices;
- gives typography, spacing, composition, color, and shape named jobs;
- distinguishes approved direction from experiments;
- produces credible print proofs before Canva templates are built;
- remains reusable when digital design resumes;
- lets a later agent act without silently inventing Jukkai's identity.

## 2. Intended outcome

Create **Visual Foundations v0** inside the existing Figma project/file
`Jukkai — Visual Identity`.

The result should be a self-demonstrating operational workroom:

- beautiful enough for the foundation to feel credible and inspiring;
- structured enough for Martin, Crystelle, and later agents to use;
- visibly unfinished where decisions remain open;
- built from the actual Jukkai typefaces, marks, colors, and real content;
- expressed primarily through specimens and applied compositions rather than
  long descriptive prose.

Visual Foundations v0 is cross-medium. Print is its first and urgent proving
ground, not its permanent boundary.

### Required proving grounds

The foundation must be exercised through:

1. a business-card system with the same underlying composition for Crystelle
   and her collaborator;
2. one A5 flyer composition;
3. one tightly bounded responsive specimen showing the same editorial content
   at a mobile and desktop width.

The responsive specimen validates transferability only. It is not a homepage
direction, component library, motion study, or website implementation plan.

## 3. Status and authority model

Every meaningful Figma specimen, token proposal, asset, composition, or palette
must carry one of these states:

| State          | Meaning                                                                               |
| -------------- | ------------------------------------------------------------------------------------- |
| **Fixed**      | User-owned direction the investigation must not reinterpret.                          |
| **Adopted v0** | Current default for this investigation; reversible after evidence or proof.           |
| **Candidate**  | A proposal to compare and review; never presented as approved.                        |
| **Open**       | A real unresolved decision the work must preserve or help clarify.                    |
| **Evidence**   | An observation from a reference or existing artifact; informative, not authoritative. |

Presence in Figma does not imply approval. Visual polish does not increase an
artifact's authority.

### Decision ownership

| Owner         | Decisions                                                                                                                               |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| **Martin**    | Typographic hierarchy, spacing, grids, composition quality, asset state, visual-system recommendations, and print-production readiness. |
| **Crystelle** | Factual content, whether the work feels recognizably like Jukkai, emotional relationship to color, and her personal colorway.           |
| **Joint**     | Changes to the master wordmark, adoption of a signature color, and selection of a primary symbol or seal.                               |
| **Agents**    | Investigation, proposals, comparisons, and demonstrations. Agents own no brand decision.                                                |

This boundary exists to replace unstructured choice with prepared, meaningful
review. It is not permission to hide consequential identity decisions from
Crystelle.

## 4. Governing visual direction

### Fixed

- Jukkai's stable identity should come primarily from editorial structure:
  wordmark, typographic roles, hierarchy, spacing, composition, and repeated
  alignment behavior.
- Color is an expressive layer inside that structure. Jukkai is not intended to
  be colorless, but recognizability must not depend on selecting a corporate
  accent immediately.
- The master wordmark remains single-ink. A colored tittle is an unapproved
  application experiment, not a master-mark change.

### Working creative intent

Martin's current read is **editorial premium with room for color, joy, surprise,
and some neo-brutalist energy; the editorial parent dominates**.

This is a provisional creative intent, not a visual recipe. The investigation
must not translate `neo-brutalist` mechanically into fluorescent blocks, thick
black borders, chaotic alignment, raw default typography, or arbitrary
oversizing. What actually creates Jukkai's moments of joy remains open.

## 5. Typography

### 5.1 Family registers

The foundation uses three live type families with different kinds of authority:

| Register                 | Family | Intended jobs                                                                                                  | Status                                |
| ------------------------ | ------ | -------------------------------------------------------------------------------------------------------------- | ------------------------------------- |
| **Spectacle**            | Voyage | Hero energy, atmosphere, rare display gestures, expressive fragments.                                          | Fixed role; exact cuts and uses open. |
| **Voice and authorship** | Hatton | Editorial headings, introductions, quotations, bylines, and selected short identity labels.                    | Fixed role; exact cuts and uses open. |
| **Utility**              | Frama  | Dense information, body copy, navigation, contact details, URLs, captions, labels, and practical instructions. | Fixed role; exact cuts and uses open. |

Not every composition must use all three families. Restraint is a success
condition, not evidence that a family is missing.

The wordmark's source-construction fonts do not become live identity typography
merely because they contributed glyphs to the mark.

### 5.2 System structure

Do not force the three families onto one universal modular scale.

The investigation must propose and demonstrate:

- a disciplined functional ladder for Frama;
- semantic editorial roles for Hatton;
- no more than a small number of art-directed Voyage roles;
- the hierarchy and spacing relationships that let those systems coexist.

Hatton is not restricted to conventional headings. It may carry information
when the information should feel authored, ceremonial, or editorial rather than
operational.

### 5.3 Identity-label role

Create a distinct candidate role for:

- `BY CRYSTELLE TERRASSON`;
- short uppercase attribution;
- selected editorial labels or categories.

Hatton is the leading candidate for this role. The investigation must compare
Hatton at actual print size against the relevant practical alternative and the
existing lockup baseline. It must assess:

- legibility;
- fine-stroke survival;
- tracking;
- perceived authority;
- behavior on the intended stock and print process;
- the size below which the wordmark should appear without the byline.

The existing Hellix byline in
[`visual-identity-wordmark.md`](visual-identity-wordmark.md) is historical working
evidence, not an instruction to retain Hellix in Visual Foundations v0.

### 5.4 Typography requirements

- Use real French copy and preserve accents on capitals.
- Test all print-critical roles at 100% physical scale.
- Keep body and dense functional text comfortably readable.
- Treat tracking, leading, measure, weight, and size as one system.
- Propose exact cuts, sizes, tracking, leading, and minimum sizes as
  **candidates**.
- Do not infer approval from a typeface looking impressive at specimen scale.

## 6. Color

### 6.1 Stable frame

The following roles are fixed:

- a warm ivory field;
- a near-black ink/dark field.

The following values are adopted v0 anchors:

| Role           | OKLCH working value          | Hex projection | Status                                    |
| -------------- | ---------------------------- | -------------- | ----------------------------------------- |
| Ivory field    | `oklch(0.915 0.023 84.593)`  | `#EAE2D2`      | Adopted v0; print formulation unapproved. |
| Dark ink/field | `oklch(0.230 0.004 106.693)` | `#1D1D1B`      | Adopted v0; print formulation unapproved. |

The roles must not be casually replaced during color exploration. Exact print
formulations may change after CMYK conversion, stock selection, and physical
proofing.

### 6.2 Color representation

- OKLCH is the working source for constructing, comparing, and adjusting
  palettes.
- Hex/sRGB values are delivery projections for Figma, Canva, and ordinary
  digital exchange.
- CMYK values are print-specific projections validated through proofing.
- HSL is recorded only when a delivery tool genuinely requires it.
- Multi-hue comparisons use the same lightness and the same percentage of each
  hue's available gamut chroma, not the same absolute chroma.

### 6.3 Adopted-v0 exploration grammar

- A composition may use one authored high-chroma color as its leading chromatic
  voice.
- Several supporting hues are allowed when they remain perceptually quieter and
  have named supporting jobs.
- Ivory and dark stabilize the composition.
- When photography or art already carries strong chroma, the authored accent
  should retreat or disappear.
- Color is evaluated as a role and relationship, not as an isolated swatch.
- Supporting colors must not compete as equal primaries.

This grammar is a safety default for the investigation, not the final Jukkai
palette constitution.

### 6.4 First accent hypotheses

The first palette exercise compares equal-energy accent hypotheses on the same
underlying compositions. The values below are sRGB-safe starting coordinates,
not recommendations to approve:

| Candidate | OKLCH                    | Hex       | Purpose                                                                               |
| --------- | ------------------------ | --------- | ------------------------------------------------------------------------------------- |
| Vermilion | `oklch(0.640 0.175 35)`  | `#E25B3A` | First warm hypothesis; preserves and disciplines part of Crystelle's orange instinct. |
| Cobalt    | `oklch(0.620 0.159 265)` | `#5680E5` | Cool architectural counter-hypothesis.                                                |
| Magenta   | `oklch(0.640 0.192 350)` | `#DC4F9C` | Art/fashion/joy counter-hypothesis.                                                   |

These candidates are unsuitable as normal-size text on the ivory anchor without
additional contrast work. Test them as fields, large gestures, or accents with
the correct ink pairing.

### 6.5 First supporting-color hypotheses

| Candidate   | OKLCH                    | Hex       | Purpose                            |
| ----------- | ------------------------ | --------- | ---------------------------------- |
| Soft pink   | `oklch(0.860 0.029 10)`  | `#E3CACC` | Supporting field or quiet element. |
| Soft yellow | `oklch(0.860 0.067 95)`  | `#DED19F` | Supporting field or quiet element. |
| Soft blue   | `oklch(0.860 0.029 240)` | `#C0D4E3` | Supporting field or quiet element. |

The differing absolute chroma values reflect the differing sRGB gamut available
to each hue at the same lightness. The candidates are a method demonstration,
not a settled supporting palette.

### 6.6 Required color method

1. Evaluate candidate relationships as flat fields first.
2. Apply them to unchanged card, flyer, and responsive compositions.
3. Compare hierarchy, perceived quality, recognizability, contrast, and print
   viability.
4. Only after the flat relationships work, introduce gradients, circles,
   textures, seals, or other material effects.
5. Keep the existing gradient-orb/sphere studies as source evidence and label
   them experimental.

### 6.7 Open color decisions

- Whether Jukkai should eventually own one recurring signature accent.
- Whether the leading high-chroma hue may vary between people or applications.
- Which accent, if any, is selected.
- The final supporting palette.
- Whether a colored tittle is ever permitted as an application variant.
- The role of gradients and chromatic material.

The useful idea behind the current personal-card proposal is fixed at the level
of intent: **each person may receive an individual chromatic identity inside one
shared Jukkai system**. The carrier of that variation remains open.

## 7. Spacing

### 7.1 Fixed principle

The foundation uses two gears:

1. **Local rhythm** — relationships within content: optical correction,
   label-to-value, heading-to-copy, inline spacing, and internal grouping.
2. **Compositional rhythm** — margins, column gaps, region separation, pacing,
   and deliberate voids.

The Figma investigation must make the difference visible through specimens and
applications. Spacing within a relationship should be meaningfully tighter than
spacing between separate groups or scenes.

### 7.2 Candidate work

- Propose names whose meaning is unambiguous when seen in use.
- Propose the number of useful steps and their boundaries.
- Test a print implementation informed by the existing 4 mm base-unit and 2 mm
  half-step hypothesis.
- Reject or revise that hypothesis if actual-size card and A5 evidence does not
  support it.
- Preserve the dual-gear relationship when later proposing digital values; do
  not translate millimetres mechanically into pixels.

Exact token names and values remain open.

## 8. Composition and layout

### 8.1 Shared invariants

The card, flyer, and responsive specimen should demonstrate that:

- alignment is intentional and visibly repeated;
- empty space performs structural work;
- expressive type, information, and imagery have clear relationships;
- text measure is bounded independently of the full field;
- asymmetry attaches to an underlying rail;
- hierarchy remains legible when color is removed.

### 8.2 Format-specific grids

The investigation must propose:

- a compact grid appropriate to the business card;
- an editorial grid appropriate to A5;
- a simple responsive alignment model for the mobile/desktop specimen.

The grids should feel related through alignment behavior, spacing logic, and
hierarchy. They need not share the same column count or literal measurements.

## 9. Shape language and selective softness

Do not assume either universal square geometry or universal rounding.

The foundation must investigate a **selective-softness grammar** in which
different shape treatments have different jobs:

- square or near-square editorial fields and inputs;
- minor softening;
- softly rounded controls or bounded regions;
- fully circular or pill geometry;
- architectural arches or large masks treated as composition-specific forms,
  not ordinary component radii.

### Evidence: Obsidian Assembly

The Obsidian Assembly reference is useful calibration evidence:

- `4.8px` minor utility radius;
- `9.6px` main control radius;
- `24px` large menu/link-region radius;
- `50%` or approximately `58.594px` circular/arched geometry;
- square inputs and fine hairlines;
- softly rounded, visually shallow controls against a more expressive canvas.

The rendered values are observations, not Jukkai tokens. A regularized candidate
set such as `0`, `4–5`, `9–10`, `24`, and `full` may be tested, but exact values
and applications remain provisional.

Obsidian Assembly is a calibration reference, not a template. Its overlap with
Jukkai—Voyage, warm parchment/ink, selective vermilion, and controlled
softness—makes uncritical copying a particular risk.

Do not create a complete card/button/modal/media radius system before real
objects require those roles. Do not add generic shadows, floating SaaS cards,
or habitual pills as polish.

## 10. Figma workroom requirements

Use the existing `Jukkai — Visual Identity` Figma project/file. It currently
contains seal variants on a default page.

The later execution prompt may choose exact page and frame names, but the
workroom must make these areas easy to find:

- status and orientation;
- current/fixed foundation;
- typography laboratory;
- spacing and composition laboratory;
- color and material laboratory;
- business-card proofs;
- A5 flyer proof;
- responsive foundation proof;
- current assets;
- symbol/seal laboratory;
- experiments;
- archive/source imports;
- material approved for a later Canva handoff.

### Asset-state requirements

- Preserve every existing seal variant.
- Reorganize and label them; do not delete or silently narrow them.
- Treat all current seals as candidates unless Martin explicitly selects one.
- Do not use a seal as decoration merely because a composition feels empty.
- Keep approved/current assets separate from candidates and experiments.
- An empty Current Assets area is more truthful than filling it with unapproved
  work.

## 11. Applied proof requirements

### 11.1 Business cards

- Use one shared structure for both people.
- Vary only approved candidate content or colorway roles during comparison.
- Test wordmark, byline/identity label, personal information, and contact details
  at actual size.
- Show the composition in ivory/dark before chromatic variants.
- Compare personal variation without redesigning the hierarchy for each person.

### 11.2 A5 flyer

- Exercise the three typographic registers without requiring all three if the
  composition is stronger with fewer.
- Include enough real content to test headline, voice, functional information,
  and hierarchy.
- Show the composition in ivory/dark before chromatic or material variants.
- Test display energy, image relationship, grid, pacing, and print legibility.

### 11.3 Responsive specimen

- Use the same real content at mobile and desktop widths.
- Demonstrate reading measure, hierarchy, local/compositional rhythm, and color
  behavior.
- Keep body readability stable while allowing the expressive ceiling to change.
- Do not invent a homepage, navigation system, component library, or motion
  language.

## 12. Tool and production boundary

### Figma

Figma owns visual-foundation reasoning, specimens, comparisons, asset states,
and approved composition masters.

### Canva

Canva later owns constrained self-service production templates populated from
approved Figma work. It should expose approved fonts, colors, assets, and
editable content without reopening the complete composition.

Canva template construction is outside this specification's execution scope.
Before that work begins, confirm that font licenses permit upload and shared use.

### VistaPrint and prepress

VistaPrint receives approved print-ready exports after a separate production
check. The eventual production workflow must verify current product dimensions,
bleed, safe zones, image resolution, font handling, color conversion, stock,
finish, and physical proofing.

Figma's screen color is not print approval. Hex-to-CMYK conversion is not a
substitute for a physical proof.

## 13. Required investigation outputs

The Figma work must propose, demonstrate, and label as candidates:

- exact font cuts, weights, sizes, tracking, leading, and minimum sizes;
- the Frama functional ladder;
- Hatton editorial and identity-label roles;
- the small set of Voyage display roles;
- spacing names, values, and gear boundaries;
- format-specific grids;
- shape/radius roles and candidate values;
- accent and supporting-color hypotheses;
- personal-card variation carriers;
- any material or gradient treatment worth further investigation.

Each proposal should be judged in an applied composition, not only in an
isolated token table.

## 14. Acceptance criteria

Visual Foundations v0 is ready for Martin's review when:

- fixed, adopted-v0, candidate, evidence, and open material are visibly
  distinguishable;
- the workroom itself demonstrates the proposed foundation;
- Voyage, Hatton, and Frama have specimens and applied role tests;
- byline/identity-label and small-print tests are shown at actual size;
- local and compositional spacing are visibly different;
- card, A5, and responsive alignment models are demonstrated;
- selective-softness studies show different shape jobs rather than uniform
  rounding;
- flat color hypotheses appear before gradient/material versions;
- two person-card variants share one underlying composition;
- one A5 proof and one bounded mobile/desktop proof exist;
- all seal variants survive and remain visibly unselected;
- no agent-authored choice is presented as approved;
- unresolved decisions are collected into a short review list;
- the output is strong enough to inform a detailed Canva-template execution
  plan after decisions are made.

## 15. Stop conditions

Pause the investigation and return to Martin when:

- a proposed change alters the master wordmark or lockup architecture;
- a font license blocks the intended Figma or Canva use;
- the current Figma file/project cannot be identified confidently;
- real card/flyer content or printer dimensions are missing in a way that makes
  actual-size proof misleading;
- a color choice is being treated as final without physical print evidence;
- a symbol, signature accent, or motif must be selected to continue;
- the work requires a new business, audience, or brand-positioning decision;
- scope begins expanding into complete website design, motion, or component
  production.

## 16. Explicit non-goals

This specification does not authorize or require:

- final brand guidelines;
- a complete design system;
- root `DESIGN.md` creation;
- final palette or signature-accent selection;
- seal, eye, dot, or other symbol selection;
- master-wordmark modification;
- final gradient or motif grammar;
- full website or homepage design;
- production components, interaction states, or motion;
- Canva template construction;
- VistaPrint upload or print ordering;
- deletion of exploratory assets.

## 17. Open decisions for later review

- Does Jukkai eventually need one recurring signature accent?
- Where should personal color variation live: field, accent, rule, punctuation,
  tittle, material, or another carrier?
- Which exact Frama, Hatton, and Voyage cuts survive actual-size tests?
- What is the final byline face, weight, tracking, and minimum size?
- What names and values make the two spacing gears unambiguous?
- Which selective-softness roles belong to Jukkai rather than to the reference?
- What creates joy and surprise without weakening editorial authority?
- Which seal or symbol, if any, earns approval?
- What role should gradients and painterly/ink material play?
- Which Figma decisions are stable enough to project into Canva, production
  tokens, future brand guidelines, and eventually `DESIGN.md`?
